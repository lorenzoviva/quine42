# T542 — L'id del workspace della chiave API

Stato: aperta

## Contesto

La coda pagata coi crediti API è fatta e provata offline (`npm run abbonamento -- --api --tetto-api 100`, ADR-0262). La richiesta vera di
prova (26/11, tetto 0,50 $, su una coda temporanea) è arrivata all'API con la chiave del `.env` della radice `rune`, e l'API l'ha rifiutata
**senza costi** (0 token):

> API Error: 400 This API key is not scoped to a workspace, so this request must include the anthropic-workspace-id header with the ID of
> the workspace to use. Add the header, or use an API key that is scoped to a workspace.

La chiave è dell'organizzazione, non di un workspace. La coda sa già mandare l'intestazione (dalla variabile `ANTHROPIC_WORKSPACE_ID` del
`.env`, alla CLI come `ANTHROPIC_CUSTOM_HEADERS`): con `default` l'API risponde «header must be a valid workspace ID», quindi l'intestazione
arriva, ma serve l'id vero. Senza, il servitore si ferma alla prima richiesta col motivo.

## Domanda

Come vuoi che la coda si presenti all'API?

## Opzioni

1. **(raccomandata)** Scrivi nel `.env` della radice `rune` la riga `ANTHROPIC_WORKSPACE_ID=wrkspc_…` con l'id del workspace su cui stanno i
   crediti (console di Anthropic → Settings → Workspaces: l'id del workspace, che non è un segreto). Nient'altro cambia.
2. Crea nella console una chiave **di un workspace** e mettila al posto di quella di oggi in `ANTHROPIC_API_KEY`: allora non serve l'id.

Dopo l'una o l'altra la prova è una riga (≤ 0,05 $, una coda temporanea): rilancio la richiesta vera e confronto il registro
(`spesa-api-claude.json`) col costo della console. Per spendere i 100 $ col generatore: `"api": true` (e, se vuoi, `"tettoApi": 100`) in
`generatore` di `tools/pipeline/config.json`, o `QUINE_CODA_TETTO_API=100` nel `.env`.
